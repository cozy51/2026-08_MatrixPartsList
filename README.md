# Matrix Parts List

複数のPL（CSV）を、部品を縦軸・PL番号を横軸とするマトリックス部品表へ変換するReactアプリです。CSVの帳票部と明細ヘッダーを見出し名から判定し、品番がない明細は `+` として扱います。データはIndexedDBへ自動保存されます。

## ローカル起動

Node.js 20以降を用意し、次を実行します。

```bash
npm install
cp .env.example .env.local
npm run dev
```

本番ビルドは `npm run build`、テストは `npm test` です。

## 操作

1. 「CSV・Excelを追加」、中央の初回案内、または左サイドバーの常設ドロップ領域でCSV・Excelファイルを選びます。登録済みPLがある状態でもサイドバーへ繰り返しドラッグ＆ドロップできます。Excelは先頭シートをPLとして読み込みます。
2. ファイル名が `PL名称_Ver.csv`、`PL名称_Ver.xlsx` などの場合は末尾のVer.を自動取得します。取得できない場合は、プレビューに表示される必須入力欄へVer.を入力します。
3. 改廃が `D` の明細は削除済みとして読み込み対象から除外します。保存済みデータ・JSON復元・クラウド読込時にも、改廃 `D` の明細を自動削除します。
4. PL番号、名称、Ver.、部品数をプレビューして登録します。同じPL・Ver.が登録済み、または同じ読み込み内で重複している場合は警告を表示し、重複が解消されるまで登録できません。
5. 風船列のチェックボックスで任意の複数行を選択し、「選択行のみ」で選択した部品だけに絞り込めます。ヘッダーのチェックボックスでは表示中の行を一括選択・解除できます。
6. マトリックスの各PL列では通常の使用数 `1` を `◯` で表示し、同じ部品が同一PL内に複数ある場合は実数を赤字で強調します。
7. 左のチェックでPL列を表示・非表示にします。PLには昇順に `1.`、`2.`の連番を付け、左側一覧と表ヘッダーで同じ番号を表示します。「全選択」と「全選択解除」で、現在のユニットに属するPLだけを一括変更できます。画面タイトルの右側にユニット名、キーワード検索、風船フィルターを並べています。風船が `C` の注記行は常に除外します。
8. 「PL類似度」タブでは、基準PLを選び、共通部品数を全部品の和集合で割った類似度（Jaccard係数）の高い順にPLを確認できます。各PLには左側一覧・マトリックスと共通の連番を表示します。
9. Excel出力、JSONバックアップ・復元を利用できます。削除・上書き・復元では確認画面を表示します。
10. 「ユニット名」プルダウンで27種類の属性を切り替えます。選択中の属性に属するPLだけを一覧とマトリックスへ表示します。

マトリックスのPL列はPL番号の自然順、部品行は風船番号の昇順で表示します。同じ風船番号内では、PL番号順に明細を調べたときの初出順を維持します。風船が `C` などの注記行は除外します。

同じ風船番号の行は同じ背景色でまとめ、風船番号が変わる先頭行には区切り線を表示します。隣り合う風船グループは同系統の濃淡が異なる薄いブルーを交互に使い、色の系統が変わる不自然さを避けています。品番が `+` の補材も風船番号を同一判定に含めるため、別の風船に属する補材を誤って統合しません。

左側のPL一覧と右側のマトリックスはそれぞれ独立してスクロールします。マトリックスを縦スクロールしても列の項目名は上端に固定されます。

左側の部品情報列は `風船`、`品番`、`Ver.`、`品名`、`数量`、`材質・メーカー` の順です。横スクロール時も各固定列の間に空白が生じないよう、列幅を固定しています。

CSV・Excel読み込み時はファイル名とPL名称から属性を推定します。推定できた属性はプレビューで選択済みになり、推定できない場合は登録前にユーザーが属性を選択する必要があります。

左側の登録済みPLとPL番号のヘッダーは、どちらもマウスを重ねるかキーボードでフォーカスすると、PL名称をダーク背景のツールチップで確認できます。PL番号のヘッダーは部品情報列と異なる色で表示します。PL番号へマウスを重ねるかキーボードでフォーカスすると、PL名称をダーク背景のツールチップで確認できます。PL番号とVer.は `XXX10 v11` の形式で隣り合わせに表示します。1桁のVer.は `v05` のように0埋めして2桁へ統一します。PL列と左側のPL一覧はいずれもPL番号の昇順で表示し、`HH1`で始まる標準PLには読みやすい略称 `STD` を表示します。

UTF-8 CSVに対応します。不正な文字コード、空ファイル、必須見出し（風船・品番・品名）がないファイルはエラー表示され、既存データは維持されます。

## Google Cloud / Drive設定

1. Google Cloud Consoleでプロジェクトを作成し、**Google Drive API**を有効にします。
2. OAuth同意画面を設定します。テスト中は利用者をテストユーザーへ追加します。
3. 「APIとサービス > 認証情報」で **ウェブ アプリケーション** のOAuth 2.0クライアントIDを作ります。
4. 承認済みJavaScript生成元へ開発用の `http://localhost:5173` と本番URLを登録します。
5. `.env.local` に `VITE_GOOGLE_CLIENT_ID=...apps.googleusercontent.com` を設定し、開発サーバーを再起動します。

クライアントシークレットは不要であり、フロントエンドへ設定しないでください。ログイン後は `drive.file` スコープを使い、マイドライブの `WebAppData/MatrixPartsList/MatrixPartsList-latest.json` に保存します。同期前にクラウドの `revision` を確認し、クラウドが新しければ選択画面を出します。通信エラーでもローカルデータと操作は維持されます。Googleのアクセストークンはメモリー内だけに保持します。

> `drive.file` はこのアプリが作成したファイルだけにアクセスする安全性を優先したスコープです。別環境で既に作られた同名ファイルを自動検出する必要がある運用では、Googleの審査要件を確認したうえでスコープ設計を見直してください。
